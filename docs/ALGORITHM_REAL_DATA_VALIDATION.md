## 2. 입력 변환과 사용자 프로필

원본은 snake_case 일부 필드를 가진 수집용 축약 구조이므로 `Opportunity[]`로 직접 단언해 넘기지 않는다. 테스트 내부에서만 다음 변환을 수행하고 기존 `validateOpportunity()`를 거친다.

- `posted_at → postedAt` 명시적 매핑. 원본의 id/title/tags/status/deadline/category/organizer는 유지한다.
- 누락 description은 계산용 빈 문자열, applicationStart는 미확인 null로 둔다. 제목 추출에는 본문 인수를 전달하지 않는다.
- sourceType은 학부 공지 출처에 대응하는 `knu_cse_official`을 사용한다. 누락된 collectedAt/updatedAt은 계산용 빈 문자열을 명시해 검증 함수가 실행 시각을 실제 수집 시각처럼 채우지 않게 한다. 이는 완전한 운영용 DTO가 아니며 실제 수집 시각은 미확인이다.
- 원본 source_post_id/source_url은 JSON에 보존된다. 최초 실데이터 검증 시에는 검증 함수가 선택 링크를 출력 객체에 복사하지 않았다. 후속 A 검수 수정에서는 camelCase 원문 URL 및 기존 메타데이터 보존을 보완했다. snake_case→camelCase 매핑과 DB 저장은 계속 B 책임이며 계산용 DTO와 원본을 구분한다.
- 기존 `mockUsers[0]`(user-01)을 `validateUserProfile()`으로 검증한 **동일 프로필**을 모든 전후 비교에 사용한다. 사용자 관심사는 원본 기준 웹 플랫폼, 오픈소스, 디자인 시스템, UI/UX이며 프로필 검증 후 UI/UX는 UI/UX 디자인으로 정규화되고 자유 문자열은 보존된다. 이후 추천 함수 내부 canonical 기준으로 웹 개발, 오픈소스, UI/UX로 정규화·중복 제거된다. 보유 기술은 React, TypeScript, TailwindCSS, Next.js, Git, 학습 희망 기술은 Supabase, Node.js, Docker이다. 사용자 기술·관심사를 공고에 맞추어 변경하지 않았다.

## 5. 현재 데이터의 한계와 B에게 필요한 보완

- 8건 모두 본문 없음: 모집 주제·필수/선택 기술·부정문 맥락 판별 불가. description과 실제 기술이 명시된 본문을 제공해야 한다.
- 7건 상태 확인 필요·마감일 null: 원문 검증 후 상태 및 마감일을 수집해야 한다. 제목에 마감이 있는 3번도 deadline이 누락되어 있다.
- 8번은 active지만 이미 마감: 상태 갱신 또는 신뢰할 수 있는 마감일 기반 표시가 필요하다. C의 기존 필터는 이를 정상 제외한다.
- 학사 기준 변경 안내(2번)처럼 활동 모집이 아닌 공지가 섞여 있어, 수집 분류의 적합성도 B에서 확인해야 한다.
- posted_at은 제공되지만 application_start, source_type, collected_at, updated_at 등 운영 DTO 필드가 누락되어 있다. 실제 수집·갱신 시각, 접수 기간 및 명시적 sourceType을 제공해야 한다.
