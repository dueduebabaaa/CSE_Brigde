# BRIDGE — 사용자 프로필 상세 명세서 (PROFILE_SPEC.md)

## 1. 개요
본 문서는 경북대학교 컴퓨터학부 학생들의 정체성, 전공 역량, 관심사 및 협업 성향을 정확하게 모델링하기 위한 **사용자 프로필(User Profile)의 입력 필드 명세 및 표준 태그 체계**를 정의합니다.

---

## 2. 프로필 데이터 항목 분류

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. 인증 기반 정보 (Auth Provider: Google OAuth @knu.ac.kr)                   │
│    - 고유 ID, 학교 이메일, Google 계정 이름, 프로필 사진 URL(선택)            │
├─────────────────────────────────────────────────────────────────────────────┤
│ 2. 온보딩 필수 입력 항목 (Required for Service Use)                          │
│    - 이름, 소속 학부, 세부전공, 학년, 관심 분야, 보유 기술 스택, 희망 역할      │
├─────────────────────────────────────────────────────────────────────────────┤
│ 3. 온보딩 선택 / 마이페이지 상세 입력 항목 (Optional Enhancements)           │
│    - 닉네임, 한 줄 소개, 자기소개, 기술별 숙련도, 배우고 싶은 기술,            │
│      희망 활동 유형, 활동 목표, 활동 방식, 희망 기간, 참여 가능 상태,          │
│      프로젝트 경험, 수상 이력, GitHub 링크, 포트폴리오 링크, 활동 가능 시간표   │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2-1. [인증 기반 정보] (자동 연동)
- **사용자 고유 ID (`id`)**: Supabase Auth UUID
- **학교 이메일 (`email`)**: `@knu.ac.kr` 도메인 계정 (타인에게 비공개)
- **Google 계정 이름 (`name`)**: 기본 이름 값으로 채워짐 (수정 가능)
- **Google 프로필 사진 (`avatarUrl`)**: 제공 시 초기 아바타로 적용

### 2-2. [필수 입력 항목]
1. **이름**: 실명 입력 원칙 (팀 빌딩 신뢰성 확보)
2. **소속 학부**: 경북대학교 컴퓨터학부 (직접 입력 / 기본값 세팅)
3. **세부전공 (트랙)**:
   - `글로벌소프트웨어융합전공`, `플랫폼소프트웨어전공`, `인공지능컴퓨팅전공`, `심화컴퓨팅전공`, `첨단컴퓨팅연구전공` 중 택 1
4. **학년**:
   - `1학년`, `2학년`, `3학년`, `4학년`, `대학원생` 중 택 1
5. **관심 분야 (다중 선택)**: 최소 1개 이상 선택
6. **보유 기술 스택 (다중 선택)**: 
   - *배려 옵션*: 아직 기술 스택을 확정하지 못한 1~2학년 새내기 학생을 위해 **[아직 보유 기술 없음]** 단독 선택 옵션 제공.
7. **희망 프로젝트 역할 (다중 선택)**: 최소 1개 이상 선택

### 2-3. [선택 입력 항목]
- **닉네임**: 서비스 내 표기용 별칭 (미입력 시 이름 사용)
- **프로필 사진**: 직접 이미지 업로드 가능
- **한 줄 소개**: 프로필 카드 노출용 요약 문구 (최대 60자)
- **자기소개**: 상세 소개 및 협업 성향 (최대 500자)
- **기술별 숙련도**: 보유 기술 스택별 자가 평가
- **배우고 싶은 기술 (다중 선택)**: 프로젝트를 통해 성장하고 싶은 기술
- **희망 활동 유형 (다중 선택)**: 선호하는 프로젝트 종류
- **활동 목표 (다중 선택)**: 프로젝트 참여 동기
- **활동 방식**: 선호 미팅 형태
- **희망 활동 기간**: 프로젝트 참여 호흡
- **현재 참여 가능 상태**: 팀 빌더 및 매칭 시 유효성 판단 기준
- **프로젝트 경험 (복수 등록)**: 상세 이력
- **외부 링크**: GitHub URL, 개인 포트폴리오 웹사이트 링크
- **활동 가능 시간**: 주간 30분 단위 활동 가능 슬롯 등록

## 5. 프로젝트 경험 입력 스키마 (Project Experience)

복수의 프로젝트 경험을 카드 형태로 추가할 수 있도록 구조화합니다.

```typescript
export interface ProjectExperience {
  id: string;
  projectName: string;           // 프로젝트명 (예: "2025 학부 해커톤 출전작")
  description: string;           // 프로젝트 설명 및 문제 해결 경험
  role: string;                  // 담당 역할 (예: "Frontend Lead")
  techStacks: string[];          // 사용 기술 (예: ["React", "TypeScript", "TailwindCSS"])
  period: string;                // 활동 기간 (예: "2025.09 - 2025.11 (3개월)")
  awards?: string | null;        // 수상 이력 (예: "우수상 수상", 없으면 null)
  linkUrl?: string | null;       // 관련 링크 (GitHub Repo, 배포 URL, 발표 자료 등)
}
```

## 6. 팀 C(알고리즘)의 `tagClassification.ts` 표준화 및 협업 포인트

현재 팀원 C가 별도 브랜치에서 공모전 추천 및 태그 분류 알고리즘(`tagClassification.ts`)을 병렬 개발 중이므로, 상호 호환성을 위해 다음 사항을 협의 예정 표준안으로 지정합니다.

1. **태그 대소문자 정규화 (Normalization)**:
   - UI 입력 시 `react`, `React`, `REACT`는 모두 내부적으로 정규화된 키(`React`)로 매핑되어 알고리즘에 전달되어야 합니다.
2. **기술 스택 - 포지션 역량 맵핑 규칙**:
   - `React`, `Vue`, `Next.js` $\rightarrow$ `Frontend` 역량 점수 가산
   - `Spring`, `Node.js`, `FastAPI` $\rightarrow$ `Backend` 역량 점수 가산
   - `PyTorch`, `TensorFlow`, `Pandas` $\rightarrow$ `AI/Data` 역량 점수 가산
   - `Figma` $\rightarrow$ `UI/UX` 역량 점수 가산
   - `Docker`, `AWS`, `Linux`, `GitHub Actions` $\rightarrow$ `DevOps` 역량 점수 가산
3. **'아직 보유 기술 없음' 옵션 처리**:
   - 보유 기술이 없더라도 사용자가 선택한 **희망 역할(Desired Roles)**과 **배우고 싶은 기술(Wanted Tech Stacks)**에 가중치를 부여하여, 입문자를 필요로 하는 스터디나 초급자 환영 공모전에 정상 추천되도록 C 담당자와 협의합니다.


## BRIDGE 분류 및 온보딩 연동 협의

- 전공 선택지는 `src/constants/majors.ts`를 재사용한다. 데이터과학전공은 별도 선택지에서 제외하되 기존 사용자 데이터는 변경하지 않는다.
- 신규 온보딩은 학년·전공·관심사·역할·기술·협업 성향·공개 범위를 미선택으로 시작한다. 기타 직접 입력은 별도 문자열로 보존한다.
- 보유 기술 최소 1개 또는 보유 기술 없음이 필수이며 숙련도는 선택이다. 미입력 숙련도를 자동으로 채우지 않는다.
- 공개 범위는 직접 선택한다. 회원 공개는 인증된 BRIDGE 회원만 대상으로 하며 학교 이메일은 일반 회원에게 노출하지 않는다. 실제 접근 통제·응답 필드 제외는 B 연동 시 구현한다.
- B·C 협의: 공통 `TrackType`은 이전 명칭이므로 폼 값을 그대로 API에 전달하거나 타입 단언으로 우회하지 않는다. 의미가 확인된 전공만 명시적 변환표를 합의하여 서비스 경계에서 변환한다. 심화컴퓨팅↔심화컴퓨터공학, 기존 데이터사이언스 분류, 첨단컴퓨팅연구 신규 값은 자동 변환하지 않는다. 기존 데이터는 보존한다.
- B·C 협의: 기타 관심사·역할 문자열 저장/정규화, 직접 추가 기술의 동의어 정규화, 미입력 숙련도 표현, 기술 없음의 빈 배열+별도 상태, 협업 선택값과 `혼합` 키, 3단계 공개 범위와 기존 `isPublic` 간 매핑을 확정해야 한다.
- 현재는 입력 확인만 제공하며 DB 저장 성공으로 표시하지 않는다. 입력은 페이지 내 React 상태로 유지되고 새로고침/이탈 시 소멸한다.
