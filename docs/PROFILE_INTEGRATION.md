# 프로필 화면 연동 검수 및 수동 테스트

## 작업 기준

- 브랜치: frontend-profile-integration
- 기준: origin/backend 07717a3 (develop에는 아직 B 코드 미병합)
- 실제 수정 서비스는 updateMyProfile(patch)이다. userId 인자를 받지 않고 서비스 내부에서 인증 사용자를 확인한다.
- name/nickname은 최신 코드의 수정 허용 목록에 포함된다.
- 로그인/온보딩/인증/백엔드 서비스/공통 타입/알고리즘/SQL/RLS는 변경하지 않았다.

## 데이터 경계

MyProfileProvider는 기존 useAuth를 소비한다. fetchMyProfile(user.id) 결과를 원본으로 보관하며, 편집 폼은 별도 ProfileDraft로 복사한다. updateMyProfile에 실제 변경한 허용 필드만 전달하고 서버 반환 행으로 공유 상태를 갱신한다. 마이페이지와 HomePage는 useMyProfile을 함께 사용한다. 홈의 기존 profileName prop에는 닉네임, 없으면 이름을 전달한다. 공고·추천·프로젝트 공급 코드는 변경하지 않는다.

계정 ID 변경/로그아웃은 이전 데이터를 render 단계에서 가리고 조회/저장 요청 세대가 다르면 늦은 응답을 적용하지 않는다. 이미 서버에 전달된 수정 요청 자체를 취소하거나 DB 롤백하는 기능은 아니다. 인증 사용자 결정과 권한 강제는 B 서비스 및 Supabase 책임이다.

학부(department)는 저장값 그대로 읽기 전용으로 표시한다. 세부전공(track)은 MAJOR_TRACKS 값만 선택한다. 학부와 전공 간 자동 변환은 없다. 관심 분야·역할의 기타 값은 현 B 저장 계약에 따라 배열 속 원문을 보존한다. 기타 전용 컬럼을 가정하지 않는다. 미입력 숙련도는 null/누락을 그대로 유지하고 입문 기본값을 만들지 않는다. 기술을 제거하면 연결된 숙련도도 제거한다. 누락된 visibility는 미설정으로 표시하고, 변경하지 않으면 전송하지 않는다. 공개 범위를 변경할 때만 is_public을 함께 파생한다.

원본 experiences, id, email, 권한, 생성/갱신 시각은 편집 폼 payload에서 제외된다. 모집글/초대장은 실제 조회가 없어 숫자 대신 연동 준비 상태로 표시한다.

## 자동 검증

- npm.cmd test: 12개 파일, 127개 테스트 통과 (새 테스트 24개).
- TypeScript: node_modules/.bin/tsc.cmd --noEmit.
- 프로덕션 빌드: npm.cmd run build.
- git diff --check.
- 새 테스트는 B 서비스 호출을 mock한다. 실제 Supabase 저장을 증명하는 테스트가 아니다.
- 계정 전환, 이전 계정의 늦은 조회/저장, 저장 실패 입력 유지, 변경 필드만 전달, 취소, 중복 클릭, 공개 범위/선택값 보존, 재마운트 재조회, 실제 HomePage 인사말 반영을 확인한다.

## 브라우저 검수 범위

테스트 프로필을 공급한 임시 Context harness에서 실제 ProfilePage/HomePage를 Chrome headless로 실행했다. 360/390/768/1440px에서 두 화면의 가로 overflow가 없고, 닉네임 저장 후 홈 인사말 갱신을 확인했다. 브라우저 pageerror는 0건이다. 스크린샷으로 모바일/PC 카드·입력·줄바꿈을 확인했다. 실제 OAuth/DB/전체 AppLayout E2E 검증이나 로그인/온보딩 재검수는 아니다. 임시 진입 파일은 제거했다.

## 실제 Supabase 테스트 (미실행)

테스트 계정이 제공되지 않아 실제 DB는 수정하지 않았다. 다음은 B/A가 테스트 계정으로 수행할 절차다. 비밀 키나 토큰을 스크린샷/로그/PR에 넣지 않는다.

1. 검증된 테스트 환경에서 학교 계정으로 로그인하고 /profile을 연다.
2. 프로필 전체의 현재 값(배열/숙련도/null/공개 범위 포함)을 B의 허용된 DB 조회로 기록한다. 개인정보를 공개 PR에 첨부하지 않는다.
3. 한 줄 소개만 변경하고 저장한다. Network 요청에서 변경 필드와 서버가 관리하는 updated_at만 업데이트되는지 확인한다.
4. B가 DB 행을 재조회해 다른 필드(name/nickname/department/track/기술/숙련도/경험/공개 범위/선택 항목)가 이전과 동일한지 비교한다.
5. 브라우저를 새로고침하고 변경한 소개가 유지되는지 확인한다.
6. 닉네임을 변경하고 홈으로 이동한다. 새 인사말을 확인하고 새로고침한 후에도 동일한지 확인한다.
7. 팀원 공개/비공개를 각각 저장하고 DB의 visibility/is_public 짝과 재조회 표시를 확인한다. 미설정 프로필은 무관한 필드 저장으로 공개되지 않아야 한다.
8. 숙련도를 미입력/활용 가능으로 각각 저장한다. 기술 제거 시 해당 숙련도만 제거되고 다른 기술 값은 보존되는지 확인한다.
9. 통신을 차단한 상태에서 저장을 시도한다. 성공 표시가 없어야 하고 입력은 유지돼야 한다. 통신 복구 후 재시도한다.
10. 저장 버튼 연속 클릭 시 쓰기 요청이 한 번인지 확인한다.
11. 로그아웃하고 다른 테스트 계정으로 로그인한다. 이전 사용자 데이터/인사말이 없어야 한다. 느린 응답 조건에서도 확인한다.
12. 360/390px 모바일과 1440px PC에서 실제 레이아웃 안의 폼·저장·취소·오류 메시지를 확인한다.
13. 테스트 데이터는 B의 승인된 절차로 복원한다.

## B에게 확인할 사항

- department/track 의미 확정. 현재 학부 편집은 의도적으로 제외했다.
- nickname은 문서상 선택값인데 isProfileComplete는 비어 있지 않은 닉네임을 요구한다. 닉네임 삭제 시 다음 로그인에서 온보딩으로 분기할 수 있으므로 정책을 통일해야 한다.
- 기타 상세 전용 필드가 필요하면 명시적인 조회/수정 계약 제공. 현재는 배열 자유값을 그대로 왕복한다.
- mapProfileRow가 구 전공/비표준 enum을 거부한다. 기존 데이터가 존재하면 B가 읽기 호환/이행 정책을 제공해야 한다.
- 실제 부분 수정 후 미수정 필드 유지 및 계정 전환 중 서비스의 인증 사용자 선택을 검증한다.
- 동시 편집 낙관적 잠금은 현재 서비스에 없다. 필요 시 B가 버전 검사를 제공한다.

## 통합

현재는 frontend-profile-integration → backend 대상으로 리뷰하면 A 변경만 비교할 수 있다. B가 develop에 병합되면 최신 develop 기준으로 diff 및 전체 테스트를 재확인하고 develop 대상으로 전달한다. backend 기준이므로 develop의 C 최신 173개 테스트 상태와 이 브랜치의 테스트 수는 다르다. 이 작업에서는 commit/push/merge/PR 생성을 실행하지 않았다.

## 2026-11-18 계약 재확인 및 닉네임 임시 보호

- 최신 origin/backend는 d76a724이며 07717a3 이후 변경은 profileService.test.ts 테스트 2개 추가뿐이다. 서비스 구현 자체의 차이는 없다. name/nickname 허용 및 updateMyProfile(patch) 시그니처는 기준 07717a3에 이미 존재한다. B의 별도 테스트 보완 push는 완료된 상태다. 설명이 코드 반영 전 기준이었는지는 저장소만으로 확정할 수 없으므로 B에게 확인한다.
- department는 소속 학부, track은 세부전공으로 표시한다. 소속 학부는 수정 정책 확정 전까지 읽기 전용이며 값 변환은 없다.
- 닉네임은 선택 입력 정책을 유지한다. 단, 기존 닉네임을 삭제/공백으로 변경한 patch는 UI 검증에서 임시 차단하고 사유를 표시한다. 입력 초안은 유지하며 기존/새 닉네임을 입력하면 저장할 수 있다. 기존부터 빈 닉네임은 다른 정보 수정 및 홈 이름 대체 표시를 막지 않는다. 인증 및 isProfileComplete는 수정하지 않는다.
- 실제 서비스의 빈 닉네임 완료 판정 수정은 여전히 B의 후속 작업이다. 정책 수정 후 임시 UI 보호를 제거하고 삭제→재로그인 흐름을 통합 검증한다.
- 수동 테스트 추가: 테스트 계정의 닉네임을 비우거나 공백만 입력하고 저장했을 때 사유가 표시되고 DB 요청이 없어야 한다. 기존/새 닉네임으로 복원하면 다른 초안도 함께 정상 저장돼야 한다. 원래 빈 닉네임인 계정은 이름으로 표시되고 무관한 변경의 patch에 nickname이 없어야 한다. 전체 앱의 빈 닉네임 회원 분기는 B 정책 수정 후 확인한다.
- 기존 127개 자동 테스트를 유지하고 닉네임 관련 UI 회귀 테스트 3개를 추가한다. 최신 B의 테스트 2개는 merge/pull 금지에 따라 이 worktree로 가져오지 않았다.

최종 자동 검증: 기존 127개 + 닉네임 회귀 3개 = 130개 통과. TypeScript 검사 통과. 프로덕션 빌드 통과. git diff --check 통과. 보호 대상 파일의 HEAD 대비 diff 없음. 실제 Supabase 테스트는 미실행이며, 이번 보완에서는 브라우저 반응형 검수를 재실행하지 않고 기존 레이아웃 클래스를 유지했다.
