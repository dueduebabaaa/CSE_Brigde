## 구현 및 담당 경계

MyProfileProvider가 기존 useAuth를 사용해 fetchMyProfile(user.id)를 호출한다. 원본 프로필과 편집 초안(ProfileDraft)을 분리하고 updateMyProfile(patch)에 변경한 허용 필드만 전달한다. 서버 응답으로 공유 상태를 갱신하며 HomePage의 profileName에는 닉네임, 없으면 실제 이름을 전달한다. 계정 변경·로그아웃 즉시 이전 데이터를 가리고 이전 계정의 늦은 응답을 무시한다.

- department는 소속 학부로 읽기 전용 표시하고 track은 세부전공으로 표시한다. 기존 데이터의 자동 변환은 없다.
- 관심 분야/역할의 자유 입력은 현 B 계약대로 배열에 보존한다. 기타 전용 DB 필드를 가정하지 않는다.
- 숙련도 미입력은 null/누락으로 유지하고 기술 제거 시 연결된 숙련도를 정리한다.
- 공개 범위 3단계를 보존한다. 공개 범위 변경 시에만 is_public을 파생한다. 누락을 공개로 바꾸지 않는다.
- ID·이메일·권한·생성/갱신 시각·프로젝트 경험은 화면 편집 payload에 포함하지 않는다.
- 닉네임 임시 삭제 제한은 제거했다. 사용자가 삭제하거나 공백만 입력하면 문자열 계약에 맞춰 nickname: ''로 전송한다. 수정하지 않은 닉네임은 기존 공백 값이어도 전송하지 않는다. 이름 필수 검증은 유지한다. B의 50ccb08은 닉네임 없이도 프로필 완료로 판단한다.
- 온보딩의 이미지 URL 누락/오류 시 선택 테마와 이름 첫 글자(없으면 Google 이름/기존 아이콘)를 표시한다. 공통 Avatar도 이미지 오류 시 기본 아바타로 대체한다. 크기·색상 버튼·레이아웃을 유지한다.
- 모집글/초대 현황에 실제 조회가 없어 고정 숫자 대신 연동 준비 상태를 표시한다.
- A 변경은 프론트엔드·테스트·이 문서에 한정된다. App 변경은 Provider 배치뿐이고 온보딩 변경은 아바타 UI뿐이다. 인증·프로필 서비스·DB·SQL·RLS·공통 타입·알고리즘은 수정하지 않았다. 공고 공급 로직도 A가 변경하지 않았다.
